## Findings considered and rejected

So nobody re-audits these:

- "Committed AI Gateway API key in `.env.local`": FALSE - `.env.local` is
  gitignored (`.gitignore:32`) and not tracked (`git ls-files` confirms);
  the auditor read the local file off disk. No rotation needed.
- "percentile() can panic at p=100" (`transit/src/main.rs:396-406`): FALSE -
  the `lo == hi` early return covers exact indices, and `hi > lo` only when
  `idx` is fractional, which implies `idx < len-1`.
- "Variance uses n instead of n-1" (`main.rs:380`, `network_stats.rs`):
  population variance over the full population of cells/departures is a
  defensible methodology choice, not a bug. Left as is (noted in plan 003's
  out-of-scope).
- "three.js ships in the homepage bundle": FALSE - `TerrainView` is loaded
  via `next/dynamic` in `app/statistika/editorial/povezanost.tsx:25` and
  Next code-splits per route; three.js affects /statistika only, lazily.
- "No CI / add pre-commit hooks": FALSE - `.github/workflows/ci.yml` runs
  typecheck, lint, clippy, fmt, cargo test, and cargo audit on every push/PR.
- "Stop-page interval label implies pooled cross-line interval": the headline
  fact is explicitly labeled "najčešća linija" and the per-row numbers are
  per-line; the copy is already honest. (The null-row rendering IS fixed, in
  plan 001.)
- "Sakamoto day-of-week leap-year risk" (`network_stats.rs:1495`): algorithm
  is correct; the scenario (Feb 29 service exceptions) is speculative with no
  exposure in the ZET feed. Not worth code churn.
- "Stream/paginate isochrone responses": speculative payload sizes, L effort,
  CDN-cached hot path already at 69ms median. Not worth doing now.
- "Warm the JSON cache at startup" (`lib/page-data.ts`): normal cold-start
  behavior, cache warms on first hit per file. Not worth doing.
- "Re-rolled PrevNext/section markup across pSEO families": FALSE for
  PrevNext - pages import and wrap `KitPrevNext` from the editorial kit
  (`app/linije/sections.tsx:8`). Only `generateMetadata` duplication was
  real → plan 007.
- "ESLint max-lines-per-function too lenient / unenforced": it is enforced
  (`-D warnings`-style, lint is a CI gate) and files opt out with explicit
  eslint-disable comments where imperative code reads better - working as
  designed.
- "0–100 chip uses an en-dash": the no-em-dash rule bans em-dashes; en-dash
  in numeric ranges is standard typography and used consistently.
